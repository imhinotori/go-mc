<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator filesystem → host loader | `plugins/*/plugin.toml` + `.star` are operator-installed local files; the manifest fields (esp. `entrypoint`) cross into a filesystem path. |
| plugin Starlark code → tick goroutine | a registered hook runs (in Plan 02) on the single-owner tick goroutine; a runaway/panicking hook can stall or crash it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Denial of Service | a hook with an infinite loop | mitigate | Each Emit thread is built via `starlark.NewThread` which sets `SetMaxExecutionSteps(stepBudget)` (Phase-21 mechanism) — a runaway hook returns `*EvalError`, the loop continues. |
| T-22-02 | Denial of Service | a hook that panics/errors | mitigate | `Emit` wraps each hook call in a per-hook `recover()` + logs and continues; one bad hook never skips the others or kills the caller. |
| T-22-03 | Tampering | malformed manifest `entrypoint` (path traversal `../`/absolute) | mitigate | `readManifest` rejects an entrypoint containing `..` or an absolute path; the load path is always `filepath.Join(pluginDir, entrypoint)` confined to the plugin dir. |
| T-22-04 | Elevation of Privilege | a plugin declares a `capabilities` it shouldn't have | accept | Phase 22 exposes ONLY frozen scalars (no live entity/world handles), so the surface is narrow; `capabilities` is parsed + stored but NOT enforced — enforcement lands with the Phase-23 handle API (locked decision). |
</threat_model>
