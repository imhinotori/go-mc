<objective>
ONLINE-01 (the skins half, user-directed): thread the authenticated `properties []user.Property` (the `textures` skin property fetched from hasJoined) all the way to the tab-list `PlayerInfoUpdate(ADD_PLAYER)` so OTHER players render the real skin — closing the two MISSING surfaces the research's skins addendum found: AcceptPlayer DROPS the properties, and `playerInfoEntriesEncoder.WriteTo` hardcodes `pk.VarInt(0)` properties.

Purpose: online-mode fetching a skin is useless if it never reaches the wire. The fix is small and DATA-shaped: carry the already-fetched properties onto the tickPlayer, and replace the hardcoded 0-count with a real count-prefixed property loop. The per-property wire codec ALREADY EXISTS and is jar-faithful (`user.Property.WriteTo` writes String name, String value, Optional<String> signature = `Property.STREAM_CODEC`), so the encoder just needs to call it. The self-add and BOTH cross-player broadcasts (broadcastPlayerInfoAdd / sendExistingPlayersTo) route through the one encoder, so one fix covers self + others. Offline-mode -> empty properties (Steve/Alex, unchanged).
Output: with `--online-mode` set, every client renders every other player's real authenticated skin. This plan touches DISJOINT files from 18-01 (crypto/auth-wire) and depends on neither — both run in Wave 1.
</objective>
