## CRITICAL FLAG: the `getWalkTargetValue` / BlockPathTypes surface

**It exists, partially.** `server/node_evaluator.go` already ports a faithful `PathType`
(BLOCKED/OPEN/WALKABLE) + the jar `getMalus` table + `getPathType` over the snapshot. There is
**NO `getWalkTargetValue`** and **NO `PathNavigation.isStableDestination`** yet, and the `pathType`
enum has only 3 of the vanilla classes (WATER/LAVA/FENCE/DOOR are deferred, documented at
`node_evaluator.go:36-44`).

So the plan must port a **minimal** `getWalkTargetValue` exactly as the CONTEXT.md faithful-minimum
prescribes: a v1 pig has no `WALK_TARGET` memory, so `PathfinderMob.getWalkTargetValue` returns
**0.0** for every candidate -> with all weights equal at 0.0 and `generateRandomPos`'s strict `>`
tie-break, the **FIRST non-null candidate wins**. Cite this as the malus-read stub that becomes a
real block-path-type read when the wider `pathType` set lands. Do NOT invent a richer weight.

The walkability/ground-snap primitives the port DOES reuse verbatim:
- `getPathType(r, x, y, z, mobH) == pathWalkable` IS the "is this a standable column?" check
  (solid floor below + clear body above) — the `isStableDestination` analog.
- `pathRegion.solidAt(x, y, z)` IS the `isSolid` predicate `moveUpOutOfSolid` needs.

**Tension to resolve in the plan:** `getPosition` runs on the tick in `canUse`, but
`getPathType`/`solidAt` read a `*pathRegion` snapshot, not the live world. The current
`getPosition` reads no world at all. The port's ground-snap + walkability checks need world
solidity reads. Two faithful options for the plan to pick (both cite-able):
(a) a tiny local snapshot built in `canUse` (mirror `snapshotRegion`, small box), or
(b) a direct `t.blockSolidAt(x,y,z)` tick read (`server/physics.go:76`) for the
`isSolid`/walkable probe. Option (b) is simpler and tick-owned-safe (canUse already runs on the
tick); `blockSolidAt` is the SAME solidity primitive `snapshotRegion` copies, so it is faithful.

### `server/ai_goals_passive.go` — the rewrite (transform goal)

**Edit point:** replace the body of `getPosition` (lines 120-127) and add cited helper ports

**The current (buggy) draw order + no-snap** — what is being replaced (lines 120-127):
```go
func (g *randomStrollGoal) getPosition(e *Entity) (x, y, z float64, ok bool) {
	r := mobRandom(e)
	dx := float64(r.nextInt(2*strollHorizontalRadius+1) - strollHorizontalRadius)
	dz := float64(r.nextInt(2*strollHorizontalRadius+1) - strollHorizontalRadius)  // WRONG: dz before dy
	dy := float64(r.nextInt(2*strollVerticalRadius+1) - strollVerticalRadius)
	return e.x + dx, e.y + dy, e.z + dz, true   // raw e.y+dy — NO ground-snap, NO walkability
}
```
The jar draw order is **x, y, z** (`RandomPos.generateRandomDirection`: `nextInt(2*10+1)-10`,
then `nextInt(2*7+1)-7`, then `nextInt(2*10+1)-10`) — note the current code draws dz BEFORE dy,
which is ALSO a lockstep bug to fix on BOTH sides.

**The RNG source the rewrite draws through** (already exists — `ai_goals_passive.go:46-51`, do NOT
re-add):
```go
func mobRandom(e *Entity) *entityRandom {
	if e != nil && e.ai != nil && e.ai.rng != nil {
		return e.ai.rng
	}
	return newEntityRandom(defaultEntityRandomSeed)
}
```
Available methods (`ai_random.go:71-88`): `nextInt(n int) int`, `nextFloat() float32`,
`nextDouble() float64`. The port needs ONLY `nextInt` (3 direction draws per candidate).

**Radii consts** (already exist — `ai_goals_passive.go:72-75`, reuse): `strollHorizontalRadius = 10`,
`strollVerticalRadius = 7`. These ARE `LandRandomPos.getPos(mob, 10, 7)`'s args.

**The 10-try best-of-N loop shape** the new `generateRandomPos` must implement (faithful
`RandomPos.generateRandomPos`): loop 10×; each call draws a candidate (3 `nextInt` via the
direction helper) -> reject-to-nil via the GoalUtils guards + ground-snap -> weight via
`getWalkTargetValue` (== 0.0) -> keep the highest-weight, strict `>` so the first max (first
non-null) wins -> return `atBottomCenterOf(bestPos)` = `(bx+0.5, by, bz+0.5)`, or `ok=false` if
all 10 null. **No structural analog of best-of-N exists elsewhere in the codebase** (searched:
no other goal does a multi-try scan) — this loop is new, but every primitive inside it is reused.

**Draw-count contract (the lockstep care item):** every candidate draws EXACTLY 3 `nextInt`
(x,y,z) regardless of whether it is later rejected — the rejection happens AFTER the draws
(vanilla draws the direction first, then validates). The home-restriction branch in
`generateRandomPosTowardDirection` draws ZERO extra (a v1 pig has no home — port it as a cited
no-op). So the new per-`getPosition` draw budget is `3 × (candidates attempted until success)`;
the gate draw (DRAW 1) in `canUse` is unchanged.

## Shared Patterns

### Per-mob RNG (the single shared source)
**Source:** `server/ai_random.go::entityRandom` + `server/ai_goals_passive.go::mobRandom`
**Apply to:** the new direction draws on BOTH the Go `getPosition` and BOTH `.star` `stroll_can_use`.
One `e.ai.rng` per mob; Go draws via `mobRandom(e).nextInt`, Starlark via `entity.rand_int`
(`plugin_entity.go:413` -> `e.ai.rng.nextInt`). Same object, same stream. Draw the SAME count in
the SAME order on both sides or the oracle fails.

### Walkability classification (the ground-snap predicate)
**Source:** `server/node_evaluator.go::getPathType` (== `isStableDestination` / walkable check) +
`server/path_region.go::solidAt` (or `physics.go::blockSolidAt` for a live read) (== `isSolid`).
**Apply to:** the new `moveUpOutOfSolid` + `isStableDestination` + `getWalkTargetValue` helpers.
Reuse `pathWalkable`; do NOT re-derive a solidity test.

### Faithful-scope cited stubs (never bake away)
**Pattern (already used pervasively in these files):** port a vanilla guard as a cited Go function
that currently evaluates to the vanilla default, structured to become a real read later. Examples in
this very file set: `navigation.go::canFloat` (flag ported, pathing deferred),
`node_evaluator.go` water/lava malus (deferred with cite). The plan applies the same discipline to
`getWalkTargetValue` (==0.0), `isOutsideLimits`/`isRestricted` (==false for a flat-world pig), and
the home branch in `generateRandomPosTowardDirection` (zero extra draws, cited no-op).

### Block-coordinate flooring
**Source:** `server/physics.go:67` `func floorI(v float64) int { return int(math.Floor(v)) }`
**Apply to:** `BlockPos.containing(...)` (floor each axis) and `atBottomCenterOf` (`bx+0.5, by, bz+0.5`).
