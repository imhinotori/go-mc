<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted 26.2 client → tick (health/respawn intents) | The client only REQUESTS respawn (ClientCommand); it never sets its own health. A malicious client cannot claim "I'm not dead" or set health — those are server-owned. The respawn request is decoded defensively on the owner goroutine. |
| Tick snapshot → off-tick disk IO | The player/entity snapshot crosses to off-tick IO. The snapshot is an immutable value copy taken on the owner (no live pointer crosses), mirroring the Phase-4 chunk-result discipline. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-6-05 | Tampering | a client claiming its own health / "I'm not dead" | mitigate | Health is SERVER-owned tick-owned state; the client has NO health-setting packet — it only sends ClientCommand(PERFORM_RESPAWN). The server drives death (PlayerCombatKill) and respawn. Asserted by TestCombat (damage→death is server-driven) + TestRespawnFlow. |
| T-6-04 | Denial of Service | a malformed ClientCommand / respawn request | mitigate | ClientCommand decodes the VarInt enum defensively (Scan error → no-op, never panic); an out-of-range enum is ignored. |
| T-6-15 | Tampering/race | off-tick IO reading a live tick-owned player while the tick mutates it | mitigate | The save path takes an IMMUTABLE snapshot on the owner goroutine (a value copy), then the off-tick IO operates on the snapshot — no live tick-owned pointer crosses (the Phase-4 chunk-result discipline). Proven by the Docker -race gate. |
| T-6-16 | Tampering | a corrupt/forged .dat on load crashing the join | accept/mitigate | loadPlayer falls back to spawn defaults on a read/parse error or a missing file (never crashes the join); the .dat is server-written (not attacker-supplied over the network), so the risk is low. Asserted by TestLoadMissingDefaults. |
