## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bot (client) → server | the bot is an untrusted proto-776 client driving the gate; the server validates its packets as it would any client |
| plugin hook → wire (chat) | a plugin's chat() reaction crosses into the player-facing wire via the sink |
| gate assertions → CI verdict | a false-pass assertion would close v4 on an unverified gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-02 | Tampering | the bot gate assertions | mitigate | Each item asserts the SPECIFIC observed effect (an AddEntity id that accrued move packets; a non-empty result slot then a consume; a SystemChat containing "gate_events:"), never a blanket "got packets". A missing trigger FAILS (per-item "triggered but not observed → FAIL"). exit 0 only when ALL items genuinely pass. The transcript is captured for audit. |
| T-28-06 | Information disclosure | the chat() sink broadcasting plugin text to all players | accept | The gate_events plugin broadcasts only a benign event marker; the sink is the server-controlled broadcastSystemChat (the same path player chat uses). A production plugin choosing chat() opts into broadcasting — this is the documented behavior of the builtin, not a leak. |
| T-28-07 | Spoofing | the offline gate launch accepting unauthenticated logins | accept | run-gate.sh is OFFLINE by design so the in-process bot can connect; it is a developer/gate launch, not the operator's online-mode production run (run-debug.sh keeps SULFUR_ONLINE_MODE=1). Documented at the top of run-gate.sh. |
| T-28-08 | Elevation of Privilege | the chat() builtin reaching server state from the sandbox | mitigate | chat() only invokes an installable string sink (broadcastSystemChat) — no entity/world handle, no capability bypass. With no sink installed it falls back to log(). The sandbox surface widens by exactly one server-controlled text-output seam. |
</threat_model>
