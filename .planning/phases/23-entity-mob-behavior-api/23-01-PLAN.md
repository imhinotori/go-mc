<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Starlark plugin code -> Go tick-owned game state | A plugin callback (Wave 2) reaches live entity/world state ONLY through these handles. The handle is the trust boundary: it owns re-resolution, capability checks, and seam routing. |
| Plugin manifest (capabilities) -> handle authority | The declared `capabilities` field is the least-privilege grant; the handle enforces it per-op. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Tampering / data race | entityHandle holding a live *Entity that escapes the tick goroutine | mitigate | Handle stores `id int32`, never `*Entity`; every read re-resolves `t.entities.get(id)` on the tick goroutine (Pitfall 2). Freeze() is a no-op. The -race proof lands in Wave 2 (declared-mob ticking). |
| T-23-02 | Tampering / elevation of privilege | A plugin without `world.write` mutating the world via set_block | mitigate | capSet enforcement at the handle-op boundary: `set_block` requires capWorldWrite or returns capError (a Starlark error, not a silent no-op). Same for entities.write/world.read/nav. |
| T-23-03 | Tampering | A handle mutate writing a raw field (e.x / corrupting the bucket index / clipping a wall) | mitigate | move_to routes through setWantTarget->nav->moveEntity (swept collision + re-bucket); set_block through SetBlock+broadcast; set_attribute through attribute.Map. The ONLY direct field write is set_velocity (vx/vy/vz) — the LOCKED faithful exception (tick-owned, collision-integrated next tick by tickPhysics; Entity.setDeltaMovement is a direct write). A POSITION write is forbidden (TestNoRawPositionWrite). |
| T-23-04 | Tampering | A declared attribute outside the valid envelope (e.g. negative max_health) | accept (clamped) | attribute.Map / RangedAttribute.sanitizeValue clamps to [min,max] (the verified 1:1 fold) — a bad value is clamped, not honored. No extra mitigation needed. |
| T-23-05 | Denial of Service | A non-living type silently gaining (or a living type missing) an attribute map after the coverage fix | mitigate | The fallback gates on a living-type predicate (data/entity Type category); item/arrow/boat stay nil (TestNonLivingStillNil), every living type gets at least the createLivingAttributes base (TestLivingFallback). |
</threat_model>
