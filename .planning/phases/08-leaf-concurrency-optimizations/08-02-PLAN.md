<objective>
OPT-01: swap the synchronous A* executor for the Wave-0 ants pool behind the Phase-7 pathfinding seam — the CLEANEST swap because `computePath` is already PURE over an immutable snapshot. Today `requestPath` (navigation.go:93) does `n.path = computePath(req)` INLINE on the tick. This plan makes it build the same immutable `snapshotRegion` ON the tick, then SUBMIT the pure `computePath(req)` to `t.pathPool` and return immediately — the mob keeps its current action while the A* runs off-tick (paths tolerated 1+ ticks late). The result rejoins as `pathReady{mobID, target, path}` via the UNCHANGED `applyAsyncResults` seam, where `pathReady.applyTo` (the Wave-0 contract, filled here) re-validates the mob still exists and the target is unchanged before adopting the late path.

This is a swap of the EXECUTOR, not a rewrite: `computePath` does not change a single line (its purity is the whole point), the snapshot is still owner-built, the recompute cooldown + maxVisited budget DoS guards survive, and the pipeline order is untouched. The late-result validation (drop a path for a despawned/retargeted mob) is the load-bearing safety — a late path is the norm, not the exception, so `applyTo` carries a `mobID` + `target` value and re-checks on the owner, NEVER a live `*Entity` pointer.

Purpose: OPT-01 ("async pathfinding swaps the synchronous A* executor for a goroutine pool behind the Phase-7 seam, paths tolerated 1+ ticks late") + its slice of OPT-06 (this subsystem -race clean). The A* compute is the heaviest per-tick AI cost; moving it off-tick is the headline Leaf optimization.
Output: navigation.go (requestPath submit-and-continue + pending tolerance), async.go (pathReady.applyTo filled), the tests. New external deps: none (ants/v2 landed in 08-01).
