<objective>
Build the new `world/` package — the server-side chunk subsystem — entirely as PURE code with no dependency on the tick loop (that wiring is Plan 04-03). Four pieces:

1. **Superflat generator (WORLD-04):** a deterministic `Generate(pos) *level.Chunk` — bedrock floor, solid stone to a fixed surfaceY, air above, plains biome, heightmaps computed from the profile. Same input → identical bytes. Section count is a parameter (derived from `dimType.Height/16`, never hard-coded).
2. **Chunk manager:** a plain `map[level.ChunkPos]*holder` with per-holder load state (Empty/Loading/Ready) — store/query only; it is owned by the tick goroutine in Plan 04-03 (single-owner, like `players`).
3. **Off-tick worker (WORLD-01 worker side):** a goroutine that takes a chunk request, tries `region.ReadSector` → `level.ChunkFromSave` (reusing the fork's Anvil IO wholesale), falls through to `gen.Generate` on a miss, and emits an immutable `ChunkResult{pos, chunk, err}` on a results channel. `golang.org/x/sync/singleflight` dedups concurrent requests for the same key.
4. **Packet assembly (WORLD-02 full + WORLD-03 light):** `WriteLevelChunkWithLight(cx, cz, chunk)` builds the top-level `Int x, Int z, chunkData, lightData` packet over the (now correctly-encoded, post-04-01) chunk, plus the small `SetChunkCacheCenter/Radius` and `ChunkBatchStart/Finished` builders the streamer (Plan 04-03) needs.

Purpose: This is the heart of the world subsystem. It is deliberately decoupled from `TickLoop` — the worker computes immutable `*level.Chunk` values off-thread; the tick (Plan 04-03) is the only thing that mutates the manager map and enqueues packets. That decoupling is what makes the off-tick rejoin `-race` clean and lets Plan 04-03 wire a concrete `chunkReady` (which needs `*TickLoop` internals) in the `server` package. Reuse the fork's correct primitives (`PaletteContainer`, `BitStorage`, `ChunkFromSave`, `region.Region`, `EmptyChunk`) wholesale — this package is glue + a stub generator, not a codec.
Output: `world/{generator,manager,worker,packet}.go` + their tests, and `golang.org/x/sync` added to go.mod. The ONE new dependency this phase needs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Off-tick worker → tick (via ChunkResult) | The worker computes off-thread; only an immutable ChunkResult may cross to the tick. A mutable shared chunk would be a data race. |
| Untrusted .mca sector → save.Chunk decode | Region sector bytes (potentially corrupt/attacker-influenced on a shared host) must be bound-checked before allocation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-02 | Denial of Service | Unbounded gen goroutines / duplicate generation for the same chunk under request spam | mitigate | singleflight collapses concurrent same-key requests to one generation; the worker uses a BOUNDED request channel (a full channel applies backpressure on the requester, never spawns unbounded goroutines). One worker goroutine for v1 caps concurrency. |
| T-4-03 | Tampering / DoS | Malformed `.mca` sector (negative/huge declared length) | mitigate | Reuse region.ReadSector's existing guards (ErrSectorNegativeLength, ErrTooLarge, length > 4096*num, 1MB cap) — never make([]byte, length) before the check. A corrupt-region error is surfaced as ChunkResult.err, not silently regenerated. |
| T-4-05 | Tampering | A mutable *level.Chunk shared across the worker/tick boundary (future data race) | mitigate | ChunkResult is immutable-by-contract: the worker hands off ownership and retains no reference; the tick (Plan 04-03) is the sole mutator. Proven by the Docker -race gate on world/ + server/. (region.Region is "Not MT-Safe" — owned by the single worker goroutine, never shared.) |
</threat_model>
