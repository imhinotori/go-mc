<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted client socket → handshake/login decode | Handshake fields (protocol, intention) and LoginStart (name, uuid) are attacker-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Spoofing/Tampering | Mismatched/forged protocol number on login | mitigate | Assert `protocol == 776` on the login path; mismatch → readable Login Disconnect, never silent. Status path intentionally ungated so a mismatched client still sees a version label (not a vuln — read-only status). |
| T-2-03 | Information Disclosure | Compression threshold mismatch / negotiated on one side | accept (mitigated upstream) | `MojangLoginHandler.AcceptLogin` sends Set Compression and `SetThreshold` in the correct order before LoginSuccess; both Pack/UnPack read the same `Conn.threshold`. Reuse as-is; do not re-implement (re-implementing is where ordering bugs arise). |
| T-2-08 | Denial of Service | Unbounded/garbage handshake before login | accept | The codec's frame cap (NET-06, Plan 02-01) bounds each frame; a malformed handshake fails `Scan` and closes the conn. No additional mitigation needed in Phase 2. |
</threat_model>
