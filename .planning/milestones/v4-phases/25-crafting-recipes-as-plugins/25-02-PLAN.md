<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → crafting menu | The client sends ContainerClick slot/button/input; the grid contents are server-authoritative (the HashedStack hashes are discarded, inventory.go:207). A forged windowId/slot is rejected (resend authoritative content). |
| matcher plugin → tick-owned slots | The matcher computes the result + consume; GO applies the 1-per-cell consume over the tick-owned grid (TICK-05). The plugin never directly mutates slots. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-05 | Tampering | onTakeCraft consume | mitigate | The 1:1 ResultSlot.onTake: removeItem(cell,1) per POSITIONED used cell only — never the whole stack, never wrong cells. The item-dupe / item-eat bug (Pitfall 3) is the load-bearing fidelity check. Tested by TestResultSlotConsume (asserts exactly 1-per-used-cell). |
| T-25-06 | Tampering / Elevation | result slot client placement | mitigate | The result slot (0) mayPlace=false (take-only) — a client cannot inject a result item. The result comes ONLY from Manager.Match over server-built grid. Tested by TestCraftingResultMayPlaceFalse. |
| T-25-07 | Tampering | forged windowId / slot index | mitigate | clicked() rejects a containerID that doesn't match p.openContainer.windowID (resend authoritative); craftingResolveSlot bounds the slot index. Reuses the chest path's authoritative-resend discipline. |
| T-25-08 | Availability | grid items lost on close | mitigate | handleContainerClose for a crafting window RETURNS the grid items to the player (invAdd; overflow -> playerDrop), NOT the chest persist model (Pitfall 7). Tested by TestCraftingClose. |
| T-25-09 | Denial of Service | matcher Call on the menu hot path | mitigate | Match is called only on a grid CHANGE and a result TAKE (discrete seams, like Emit) — NEVER a per-tick scan; the Call carries the Phase-21 step budget (carried from Plan 01 T-25-01). |
</threat_model>
