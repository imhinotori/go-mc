- HeightmapUpdate algorithm (jar Heightmap.update bytecode, transcribed in 10-RESEARCH §Standard Stack 2):
  ```
  col := lz<<4 | lx
  firstAvail := bs.Get(col) + minY        // current "first Y above surface"
  if y <= firstAvail-2 { return }          // below surface-1 -> no change
  if opaque {
      if y >= firstAvail { bs.Set(col, (y+1)-minY) }  // new opaque top
      return
  }
  if firstAvail-1 == y {                    // removed the exact surface block -> rescan down
      for ny := y-1; ny >= minY; ny-- {
          if opaqueAt(ny) { bs.Set(col, (ny+1)-minY); return }
      }
      bs.Set(col, 0)                         // nothing opaque below -> floor
  }
  ```
  `opaque` is the per-type predicate of the NEW state; `opaqueAt(y)` re-tests EXISTING blocks during the downward rescan (the caller closes over the chunk + the predicate). Phase 10's Decorate is a no-op so HeightmapUpdate is not yet CALLED in production — but it is built + unit-tested now so 10-03's Neighborhood proxy + the feature phase wire it correctly (10-RESEARCH §Pitfall 7).
