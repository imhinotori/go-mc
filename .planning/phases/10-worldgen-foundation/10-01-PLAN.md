The RandomSource interface the LCG MUST satisfy (world/levelgen/random.go lines 47-64):
```go
type RandomSource interface {
    NextLong() int64                          // Java long
    NextInt() int32                           // for the LCG: next(32)
    NextIntN(bound int32) int32               // [0,bound)
    NextDouble() float64                      // [0,1)
    NextFloat() float32                       // [0,1)
    ConsumeCount(n int)                        // advance n draws
    Fork() RandomSource
    ForkPositional() PositionalRandomFactory
}
type PositionalRandomFactory interface {
    At(x, y, z int) RandomSource
    FromHashOf(name string) RandomSource
    FromSeed(seed int64) RandomSource
}
```
The Xoroshiro impl (lines 169-270) is the STRUCTURAL template for method placement + the `var _ RandomSource = (*Xoroshiro)(nil)` assertion + the existing `floatUnit`/`doubleUnit` constants (REUSE those two constants — they are the same 2^-24 / 2^-53 scales). DO NOT copy Xoroshiro's primitive BODIES — they differ (see Pitfall 1 below).

Xoroshiro's `ForkPositional` returns an `xoroshiroPositionalFactory`. For the LCG, `Fork()`/`ForkPositional()` mirror Java `LegacyRandomSource.fork()/forkPositional()` — fork returns `new LegacyRandomSource(nextLong())`; forkPositional returns a `LegacyPositionalRandomFactory{seed: nextLong()}` whose `at(x,y,z)` = `new LegacyRandomSource(Mth.getSeed(x,y,z) ^ seed)`, `fromHashOf(s)` = `new LegacyRandomSource(hash ^ seed)` (java.lang.String.hashCode, widened), `fromSeed(s)` = `new LegacyRandomSource(s)`. <key_facts>
<!-- ALL jar-confirmed in 10-RESEARCH (Code Examples + Confidence table). -->
- CONSTANTS (LegacyRandomSource): MULTIPLIER=0x5DEECE66D, INCREMENT=0xB, MASK=(1<<48)-1. Hold the 48-bit state in a uint64, mask on every step.
- setSeed: r.seed = (uint64(seed) ^ MULT) & MASK.
- next(bits): r.seed = (r.seed*MULT + INCR) & MASK; return int32(r.seed >> (48-bits)). The shift is on the unsigned 48-bit state (Java >>>), THEN truncate to int32.
- NextIntN(bound): if bound is a power of two -> int32((int64(bound)*int64(next(31)))>>31); else loop { bits=next(31); val=bits%bound; if bits-val+(bound-1) >= 0 return val }. Panic on bound<=0 (match Xoroshiro's NextIntN panic).
- NextLong: hi=int64(next(32)); lo=int64(next(32)); return hi<<32 + lo. The lo term is SIGNED (a high bit makes it negative) — DO NOT mask to unsigned.
- NextInt(): next(32) (the full 32-bit signed draw — NOT (int)NextLong()).
- NextFloat: float32(next(24)) * floatUnit (2^-24).
- NextDouble: (int64(next(26))<<27 + int64(next(27))) -> *doubleUnit (2^-53).
- WorldgenRandom (embeds *LegacyRandomSource):
  - SetDecorationSeed(worldSeed, blockX, blockZ): SetSeed(worldSeed); a=NextLong()|1; b=NextLong()|1; seed=(int64(blockX)*a + int64(blockZ)*b) ^ worldSeed; SetSeed(seed); return seed.
  - SetFeatureSeed(decoSeed, index, step): SetSeed(decoSeed + int64(index) + int64(10000*step)). NO draws.
  - SetLargeFeatureSeed(worldSeed, chunkX, chunkZ): SetSeed(worldSeed); a=NextLong(); b=NextLong(); SetSeed((int64(chunkX)*a)^(int64(chunkZ)*b)^worldSeed).
  - SetLargeFeatureWithSalt(worldSeed, x, z, salt): SetSeed(int64(x)*341873128712 + int64(z)*132897987541 + worldSeed + int64(salt)). (jar WorldgenRandom.setLargeFeatureWithSalt — pure arithmetic, no draws; constants are the vanilla region-salt magics.)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| world seed (server config) -> derived worldgen/feature/structure seeds | The LCG + WorldgenRandom consume the server-configured world seed and integer chunk/feature/structure coordinates only. No client-supplied input reaches the RNG. Determinism (same seed -> same draws) is the security property: a non-deterministic or mis-ported draw silently corrupts worldgen, it is not an injection vector. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-10-02 | Denial of Service | `NextIntN` rejection loop spinning, or `NextIntN(0)`/negative bound | accept | The rejection loop's expected iterations are <2 (java.util.Random property); bound is always a positive build-time constant from ported vanilla call sites. `bound<=0` panics (programming bug), mirroring the existing Xoroshiro `NextIntN` guard — never runtime input. |
