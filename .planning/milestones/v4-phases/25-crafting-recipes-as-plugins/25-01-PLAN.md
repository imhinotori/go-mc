<objective>
Build the recipe ENGINE and the value-returning plugin bridge — the two pure, server-independent halves of the crafting dogfood. `level/recipe` embeds + parses the jar's recipe JSON for ALL types and ports the 1:1 match (shaped shrink+mirror, shapeless multiset, cooking/stonecutting single-ingredient). `plugin/host` gains the NEW value-returning `Match` seam (`set_recipe_matcher` + `recipes` builtins + `Manager.Match`/`Remaining`) that extends Phase-22's void `Emit` into query-resolution — the API-generality proof.

Purpose: This is the load-bearing 1:1 work. Everything in Wave 2 (menu, un-stub, gate) consumes the `Match` seam and the parsed recipes. Building it first, pure and tested, isolates the bytecode-fidelity risk (the 3 pitfalls) from the menu wiring.

Output: `level/recipe/` (embed + model + parse + match, jar-cited, tested) and `plugin/host/recipe.go` (the value-returning Call seam, tested). NO server changes in this plan.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → server slots | The client's claimed item contents (HashedStack) are already discarded server-side (inventory.go:207); the grid handed to the matcher is SERVER-built from authoritative slots. The client never supplies recipe data. |
| plugin matcher → tick | The recipe-provider plugin is operator-installed code running ON the tick goroutine via Manager.Match. A hostile/buggy matcher must not hang or crash the tick. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Denial of Service | Manager.Match (matcher Call) | mitigate | Fresh starlark.Thread per call carrying the Phase-21 step budget (SetMaxExecutionSteps); a runaway matcher returns *EvalError, Match returns ok=false, the tick continues. Tested by TestMatchRunawayBounded. |
| T-25-02 | Tampering | parse.go ingredient/result name->id | mitigate | An unknown item name or recipe type is a LOUD parse error (fmt.Errorf), never a silent 0/drop — a corrupt recipe cannot silently resolve to air or skip. Tested by TestUnknownTypeLoud. |
| T-25-03 | Tampering | Manager.Match return read | mitigate | readResult validates id>0 && count>0; a matcher returning a bogus/negative result yields ok=false (no result), never a forged stack. The result template still ultimately comes from the server-parsed recipe in Wave 2's gate. |
| T-25-04 | Information Disclosure | host → server boundary | accept | The grid payload is plain frozen (id,count) scalars (no live handle, no PII); the boundary leaks nothing. Rationale: scalars only, Phase-23-independent. |
</threat_model>
