<objective>
Let players PLACE and BREAK blocks with Block Update reconciliation (ENT-03), closing the explicit research gap: `world.ChunkManager` has NO block-edit API today (it is pure holder storage). This plan adds `SetBlock(pos, state, minY)` (mapping the world block pos → column/section/local and mutating the tick-owned chunk via `level.Section.SetBlock`, which maintains BlockCount) + a `GetBlock` read, then wires the serverbound handlers: `ServerboundPlayerAction` (dig stages) drives BREAK (set air), `ServerboundUseItemOn` (block-hit) drives PLACE (set the held block state at the adjacent face). Each valid edit sends `ClientboundBlockChangedAck(sequence)` AND broadcasts `ClientboundBlockUpdate` to all players tracking that chunk (editor included) — the reconciliation contract that prevents ghost blocks (06-RESEARCH Pitfall 5).

ROUTING PREMISE (verified against server/tick.go:479-534): the dispatch switch today routes `UseItemOn`/`UseItem`/`Swing` (and the MovePlayer*/Attack/Interact/PlayerInput set) into the subtick buffer, but it does NOT route `ServerboundPlayerAction` — that currently falls through to the `default:` no-op (tick.go:532). This plan MUST add `ServerboundPlayerAction` to the tick.go dispatch switch (route it into the subtick buffer exactly like `UseItemOn`) AND add the on-tick resolution in `applyInput`'s switch (server/subtick.go). `UseItemOn` is already routed into the buffer; this plan only adds its resolution.

Edits are server-AUTHORITATIVE: out-of-reach or unloaded-chunk edits are rejected (no mutation, no ack); every decode Scan-errors to a no-op. All mutation is tick-owned (TICK-05), zero new dependencies.

Purpose: ENT-03 "players can place and break blocks with Block Update reconciliation" is the most tangible interactive behavior — and the new ChunkManager.SetBlock is the explicit gap the research flagged. The ack/broadcast handshake is the load-bearing anti-ghost-block contract.
Output: world.SetBlock/GetBlock, the block-interact handlers, the BlockUpdate/BlockChangedAck encoders, the dispatch routing of PlayerAction (NEW) + the applyInput resolution, and the tracker broadcast. ZERO new dependencies.
</objective>
