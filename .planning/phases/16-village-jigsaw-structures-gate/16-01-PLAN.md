<objective>
Port the `.nbt` `StructureTemplate` system — the data-driven geometry layer villages need (STRUCT-05 part 1). This is the ONLY structure tier requiring the full templatesystem (`.nbt` parsing + `StructurePlaceSettings` + rotation/mirror + processors). It is deliberately ISOLATED from the jigsaw `Placer` (16-02): this plan delivers "given a template + a position + a rotation, place its blocks correctly"; 16-02 delivers "decide which templates go where."

Purpose: Generalize the 14-03 igloo OFFLINE-extraction shortcut (which baked the igloo `.nbt` palette/blocks into `igloo_data.go` at build time) into a RUNTIME `.nbt` parser + placer. The igloo proved the schema (size / palette of {name,props} / blocks of {x,y,z,paletteIndex}) and the `block.State.Block() -> block.ToStateID` resolution; this plan reads the same schema at runtime from embedded `.nbt` bytes and adds rotation/mirror/offset + the block-replace processors.

Output: a `StructureTemplate` Go type + `placeInWorld`, the village `.nbt`/`template_pool`/`processor_list` data embedded, the block-replace processors villages use — all round-trip tested. NO jigsaw Placer, NO village StartGenerator yet (16-02).
</objective>
