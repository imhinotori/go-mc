<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> login handler (EncryptionResponse) | The client supplies the RSA-encrypted shared secret + verify token; both are server-decrypted and the token is verified against the server-issued challenge |
| server -> sessionserver.mojang.com (hasJoined) | Out-of-band HTTPS; the server trusts Mojang's profile response for the authenticated UUID/skin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-01 | Tampering | EncryptionResponse verify token | mitigate | The decrypted verify token is `bytes.Equal`-checked against the server-issued challenge (FAITHFUL encryptionResponse) — a mismatched/forged response is rejected before the cipher is enabled |
| T-18-02 | Spoofing | hasJoined identity | mitigate | The authenticated UUID/name come from Mojang's hasJoined response keyed on the shared-secret-derived server hash (authDigest) the client could only produce by completing the real key exchange — not from a client-supplied field |
| T-18-03 | Information Disclosure | post-handshake stream | mitigate | AES-128/CFB8 (FAITHFUL) wraps all bytes after the EncryptionResponse; the SetCipher-before-auth ordering ensures the hasJoined-derived profile flows over the encrypted channel |
| T-18-04 | Denial of Service | RSA decrypt on login | accept | One 1024-bit RSA decrypt per login attempt, bounded by the existing connection cap; matches vanilla's per-login cost |
</threat_model>
