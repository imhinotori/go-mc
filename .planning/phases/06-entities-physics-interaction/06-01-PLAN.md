<objective>
Build the ENT-01 FOUNDATION every other Phase-6 slice needs: a tick-owned entity store, a monotonic entity-ID allocator that REPLACES the hard-coded `joinEntityID=1`, and per-section grid bucketing for the tracker's broad phase. Today `play_join.go:50` hard-codes `const joinEntityID = 1` — fine for the single bootstrap player, but a collision the moment entities or a second player coexist (06-RESEARCH Pitfall 7). This plan adds a real allocator (tick-owned `int32` counter, allocated off-tick at AcceptPlayer exactly like the existing teleport id), an `Entity` struct with snapshot-friendly plain-value hot fields (so the Phase-8 async tracker can copy a cheap immutable snapshot — ROADMAP note), and an `entityStore` with per-chunk-section grid bucketing (NOT a quadtree, per CLAUDE.md — vanilla buckets entities per section) exposing a `near(x,z,range)` broad-phase query.

This plan provides the STORE and the ALLOCATOR only. The synchronous tracker that diffs visibility and emits AddEntity/Move/RemoveEntities is Plan 06-02; movement/physics is 06-03. Everything here is tick-owned, single-owner (TICK-05), zero new dependencies.

Purpose: ENT-01's entity model is the dependency root of the whole phase — the tracker, physics, persistence, and the block/inventory/combat slices all reference entities or the allocator. Replacing the hard-coded id is the explicit research gap (Pitfall 7) that unblocks "entities + multiple players coexist".
Output: server/entity.go (the Entity struct + AABB helper), server/entity_store.go (the store + bucketing + allocator), the TickLoop store/allocator fields, and the AcceptPlayer/bootstrap rewiring off the const. ZERO new dependencies.
