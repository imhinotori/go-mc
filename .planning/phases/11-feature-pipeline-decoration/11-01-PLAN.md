<objective>
Deliver the DATA half of FEAT-02: extend the codegen extract set + the embed FS to ship the 226 configured_feature + 262 placed_feature + 66 biome JSON trees, and build the polymorphic `"type"`-tagged parser that loads ALL of them into a typed AST — modeled exactly on v1's `density.Registry` registry-dispatch decoder. This is the parse-and-bind foundation plans 11-02 (the modifier bodies) and 11-03 (the orchestration) consume.

**Phase 11 is ORCHESTRATION, NOT feature bodies.** This plan PARSES every configured_feature + placed_feature even though the feature TYPES they reference (tree/ore/random_patch/...) aren't implemented yet. The parser produces a **typed-but-body-deferred** AST: it records the feature type + captures its config (resolving block-state refs to `block.StateID` now), but the actual `Feature.place` body is Phase 12+'s job. A KNOWN feature type (the full vanilla roster) parses without erroring; a GENUINELY unknown type errors loudly naming it (the density-parser `end_islands` precedent — never silent mis-evaluation).

Purpose: every downstream piece (the modifier chain in 11-02, `applyBiomeDecoration` + `FeatureSorter` in 11-03) needs the parsed placed_feature/configured_feature graph + the per-biome feature lists. Building the data + parser FIRST, file-disjoint from 11-02's modifier bodies, lets the two run in parallel.
Output: the extended extract tooling + embed FS, the new `world/levelgen/feature` package (typed AST + polymorphic parser + block-state resolver + registry), and the LoadAll test proving all 226+262 entries parse clean.
</objective>
