<objective>
Stand up the network↔tick concurrency seam (NET-05), lock down the framing/compression/cap assertions over the existing codec (NET-06), and add a state-aware readable Disconnect helper (NET-07). This is the plumbing wave: it defines the per-connection Client with exactly one writer goroutine, a read goroutine that produces Intents onto an inbound channel drained by a STUB consumer, and a bounded-with-disconnect backpressure policy — shaped so Phase 3's real tick loop attaches to the same channel type without rework. The codec already enforces VarInt/VarLong framing, zlib threshold, and the 2^21 cap; this wave proves it with tests rather than re-implementing it.

Purpose: NET-05 is the load-bearing architectural invariant for the entire project — "game state is mutated only by the tick-owning goroutine" must hold from day one (it is the cheap single-threaded version of TICK-05). Getting the channel types and single-writer invariant right now is what keeps Phase 8's async swap additive instead of a rewrite. NET-06/07 are assertions and a small helper over primitives that already exist.
Output: `server/client.go` (Client + read/write goroutines + inbound seam + bounded backpressure + stub consumer), `server/disconnect.go` (state-aware reason), the shared `net.Pipe` test harness, the NET-05 `-race` seam test, and extended NET-06 cap/threshold tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted client socket → server decode | Every inbound packet is attacker-controlled: malformed frames, oversized length prefixes, compression bombs, slowloris-style incomplete frames |
| Network goroutines → game state | Read/write goroutines must never reach game state; the inbound channel is the only legal crossing (becomes the tick boundary in Phase 3) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-02 | Denial of Service | Oversized packet length prefix | mitigate | The 2^21 `MaxDataLength` cap in `net/packet/packet.go` rejects oversized uncompressed lengths before allocation. Assert with `TestMaxDataLength` (uncompressed path) — reject, no panic, no large alloc. |
| T-2-03 | Denial of Service | Compression bomb (small compressed → huge decompressed) | mitigate | The compressed path guards the declared `DataLength` against `MaxDataLength` (packet.go:183) before inflating. Assert with `TestMaxDataLength` (compressed path) — a frame declaring `DataLength > MaxDataLength` is rejected. |
| T-2-04 | Denial of Service | Slow client / unbounded outbound growth | mitigate | Bounded outbound `ChannelQueue(N)`; `Push()==false` (full) → disconnect-on-full. No unbounded `LinkedQueue` on the outbound path. Assert with a fill-then-disconnect test. |
| T-2-07 | Tampering | Game-state access from a network goroutine (future data race) | mitigate | NET-05 invariant: readLoop/writeLoop hold no game-state pointer; only move bytes + Intent. Enforce with a `-race` seam test now (catching it in Phase 3 is too late). |
| T-2-05 | Repudiation | Silent disconnect (no reason) | mitigate | State-aware Disconnect helper emits a readable `chat.Message` for Login/Config/Play; failure paths never bare-`Close()` without a reason where a reason is sendable. |
</threat_model>

    ```go
    type Intent struct {        // what the read goroutine produces — raw, undecoded beyond ID
        Client *Client
        Packet pk.Packet        // dispatched by the tick consumer, NOT here
    }

    type Client struct {
        conn     *net.Conn
        outbound PacketQueue     // NewChannelQueue(N): exactly one writer drains this
        // NOTE: no game-state pointer here in Phase 2.
    }

    func NewClient(conn *net.Conn, outboundCap int) *Client { /* outbound = queue.NewChannelQueue(outboundCap) */ }

    // writeLoop is the ONE writer. Pull() blocks; ok=false when the queue is Closed.
    func (c *Client) writeLoop() {
        for {
            p, ok := c.outbound.Pull()
            if !ok { return }
            if err := c.conn.WritePacket(p); err != nil { return }
        }
    }

    // readLoop decodes into Intents. It NEVER touches game state.
    func (c *Client) readLoop(inbound chan<- Intent) {
        for {
            var p pk.Packet
            if err := c.conn.ReadPacket(&p); err != nil { return }
            inbound <- Intent{Client: c, Packet: p}
        }
    }

    // Send enqueues outbound with bounded backpressure: full → disconnect-on-full (T-2-04).
    func (c *Client) Send(p pk.Packet) {
        if !c.outbound.Push(p) { c.Close() } // drop-and-disconnect
    }
    ```
