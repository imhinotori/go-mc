## Decisions Made
- **Ported the full `WaterAvoidingRandomStrollGoal.getPosition`, not bare `LandRandomPos.getPos`.** Verified via javap/CFR that the Pig's `WaterAvoidingRandomStrollGoal(mob,1.0)` (probability 0.001f) rolls a `nextFloat()` gate and — for a not-in-water pig — takes `DefaultRandomPos.getPos` (≈99.9%) or `LandRandomPos.getPos` (≈0.1%). The plan's `LandRandomPos.getPos`-only target was incomplete; the full method is the 1:1 truth. Both branches draw the same count (1 nextFloat + 30 nextInt), preserving lockstep.
- **Always up-snap the committed target (user-approved optimization, CONTEXT `<decisions>`).** Bare DefaultRandomPos commits underground targets that vanilla's A* resolves to a surface node at path time. Our `groundNavigation` arrives by reaching the target block, so an underground target wedges. Eagerly snapping every committed target to the same surface column the vanilla A* would resolve it to preserves observable gameplay. `wantLandMode` is recorded for the deferred no-up-snap branch.
- **`reducedTickDelay(120)==60` is the faithful gate** (`Mth.positiveCeilDiv(n,2)`); the prior raw-120 roll was unfaithful and halved the stroll cadence.

**2. [Rule 1 - Bug] reducedTickDelay — the stroll gate rolls nextInt(60), not nextInt(120)**
- **Found during:** Task 2 (the gate fired too rarely for the pig to amble).
- **Issue:** `RandomStrollGoal.canUse` rolls `nextInt(reducedTickDelay(interval))` == `nextInt(ceil(120/2))` == `nextInt(60)`. The prior v1 used the raw 120, halving the faithful cadence.
- **Fix:** Added `reducedTickDelay(ticks) = (ticks+1)/2` (cited Goal.reducedTickDelay / Mth.positiveCeilDiv); applied to the Go gate AND both .star (`STROLL_REDUCED_INTERVAL = 60`) in lockstep.
- **Files modified:** server/ai_goals_passive.go, both .star.
- **Verification:** javap Goal.reducedTickDelay + Mth.positiveCeilDiv; oracle GREEN.
- **Committed in:** c90c05ea, f1be5cd6

**3. [Rule 1 - Bug] Navigation arrival cleared the WRONG hasTarget field**
- **Found during:** Task 2 (the pig reached a reachable target but never re-rolled — still wedged).
- **Issue:** `navigation.tick` on arrival set `n.hasTarget=false` (the navigation's own field, used by shouldRecomputePath) but NOT `mobAI.hasTarget` (read by the stroll's canContinueToUse). So a reachable target the A* completed within reachRange left the stroll goal running forever. (The old underground targets masked this — the mob never arrived.)
- **Fix:** Added `markArrived(e)` clearing BOTH fields, with a pending-guard (do not markArrived while a fresh path is in flight, else it clobbers the just-committed target).
- **Files modified:** server/navigation.go.
- **Verification:** TestPigStrollsWithoutWedging GREEN; TestNavigation* GREEN.
- **Committed in:** c90c05ea

**4. [Rule 3 - Blocking] Cross-region plugin handle resolution (owningRegion fallback)**
- **Found during:** Task 3 (the oracle diverged at tick 79 — plugin callback errored "entity no longer exists").
- **Issue:** The faithful stroll walks the mob across a region seam (checkerboard `regionOf`). The plugin's region-bound nav/entity handle binds to the position-derived region, but the store entry transfers 1+ ticks later (or never in the direct-drive oracle harness) — so `store().get(id)` missed and the goal silently stopped, desyncing the oracle. The Go-native pig (reads e.ai directly) was unaffected.
- **Fix:** `navHandle`/`entityHandle.store()` fall back to `owningRegion(id)` when the position-bound store lacks the id.
- **Files modified:** server/plugin_entity.go.
- **Verification:** TestPluginPigEqualsGoNativePig GREEN (no "no longer exists" errors).
- **Committed in:** f1be5cd6
