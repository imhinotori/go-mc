Port the vanilla GoalSelector AI model into Go (AI-01) — the first slot of Phase 7 — so a mob has a goal-selector behavior model driven by the tick. This is the STANDING MANDATE in action: read the real `net.minecraft.world.entity.ai.goal.*` sources from the unobfuscated 26.2 jar (`temp/cache/26.2-inner.jar`, javap-able) and translate the ALGORITHM faithfully into idiomatic Go (non-1:1, never a GPL paste) so a Pig behaves identically to a real server. Per the resolved Open Question 1, use the classic `GoalSelector` (NOT the heavier Brain/Behavior memory system) — a v1 passive Pig is a classic-GoalSelector mob.

This plan delivers THREE things: (1) `server/ai_goal.go` — the ported `GoalSelector` + `Goal` interface + `Goal$Flag` bitset + `WrappedGoal`, whose heart is the CONTROL-FLAG LOCKING that arbitrates conflicting goals (07-RESEARCH Pitfall 4 — without it a stroll and a panic both claiming MOVE make the mob jitter); (2) `server/ai_goals_passive.go` — the concrete passive Pig goals (RandomStroll/LookAtPlayer/RandomLookAround) with the EXACT priorities and flag sets read from `javap animal/pig/Pig.registerGoals`; (3) `server/ai_mob.go` — per-mob AI state plus the driver in the jar-confirmed `Mob.serverAiStep` order. It does NOT yet wire `tickAI()` or move the mob — navigation lands in Plan 07-02 and the `tickAI()` call site + spawner land in 07-03. A goal's `tick()` only SETS a navigation/look target; it never moves the mob itself.

Everything is SYNCHRONOUS on the tick goroutine over tick-owned mob state (TICK-05). ZERO new dependencies (NO xsync/ants/conc — that is Phase 8).

Purpose: AI-01 "mobs have a goal-selector/brain behavior model driven by the tick" is the foundation the navigation (07-02) and spawner (07-03) build on — a mob with no goal model has nothing to navigate. The flag-lock arbitration is the load-bearing correctness detail.
