## OPEN DECISION D2 — RESOLVED: Option (Y) "hold until neighborhood-complete"

Phase 10's no-op Decorate made emit-on-own-decoration safe by construction. With a LIVE Decorate, a wanted center C writes features into its 8 neighbors — so a neighbor already emitted would be missing C's cross-border writes. Phase 10 named two options: (X) emit-on-own-decoration + re-send when a neighbor writes into an already-sent chunk, or (Y) hold a chunk until every center that has it as a neighbor is decorated, then emit once fully-complete.

**Bake in (Y).** Rationale:
- **Complete-on-first-send, zero re-send machinery.** (X) requires the worker (and the tick/streamer downstream) to handle re-sending an already-emitted chunk — a whole re-send protocol + idempotency on the tick side (ChunkResult is currently a single-owner immutable handoff; re-send breaks that contract). (Y) emits each chunk exactly once, fully-complete, preserving the existing immutable single-owner ChunkResult discipline untouched.
- **It is a SMALL, local change to the existing scheduler.** The worker already owns `wanted`/`staging`/`decorated` on one goroutine. (Y) = split "decorated" from "emitted": decorate a wanted center as soon as its own 3x3 is carved (so it writes into neighbors), but EMIT it only once it is decorated AND every WANTED neighbor (a center that has THIS center in its 3x3) is also decorated — after which no further write can land in it. A non-wanted ring chunk never decorates, so it never writes, so it never gates emit. This is a guard condition + a post-decoration emit-scan, not a new subsystem.
- **It is provably deterministic.** Each feature's rng is pure over (worldSeed, originX, originZ, globalIndex, stepIndex) — independent of which center decorates first (research "decoration-seed RNG chain"). So decorating A-then-B or B-then-A writes IDENTICAL blocks into the shared border. Hold-then-emit therefore yields byte-identical chunks regardless of request/decoration order — the Phase-10 5x5 reorder test still holds with a live Decorate.
- **(X) is materially WORSE here, not easier:** it would force a re-send path through the immutable ChunkResult + the tick rejoin (08-era single-owner discipline), reopening a sealed contract for no determinism benefit.

This is an EXPLICIT task (Task 4) with its own determinism + emit-once tests; the Phase-10 5x5 reorder test MUST stay green now that Decorate is non-no-op.

Output: FeatureSorter + applyBiomeDecoration + the Neighborhood->PlacementContext adapter + the upgraded Decorate + the worker D2 hold-until-complete rule, with the per-feature seed/index trace test, the FeatureSorter dedup test, and the live-Decorate determinism/emit-once suite. ZERO new deps; the tick side + ChunkResult stay untouched (the whole point of choosing Y).
