## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Off-tick pool worker → tick goroutine (async result rejoin) | A pool worker computes over an immutable snapshot and hands an immutable asyncResult to the owner via asyncIn2. The ONLY legal crossing is the immutable channel message; the worker never touches tick-owned state. This plan establishes the boundary; OPT-01/02/03 ride it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-8-01 | Tampering/race | a pool worker mutating tick-owned state off the owner goroutine | mitigate | The contract: a worker only reads its immutable snapshot and produces an immutable asyncResult; applyTo runs on the owner. async.go documents and the -race scaffold proves the boundary is clean (TICK-05). |
| T-8-02 | Denial of Service | pool saturation / goroutine blowup when many subsystems submit at once | mitigate | newAsyncPool is BOUNDED + non-blocking (ants.WithNonblocking) — Submit returns ErrPoolOverload and the work is dropped (re-requested next tick), capping goroutines (Pitfall 4). Asserted by TestAsyncPoolNonBlocking. |
| T-8-03 | Denial of Service | unbounded asyncIn2 result-channel growth | mitigate | asyncIn2 is a BOUNDED buffered channel; a non-blocking send on the worker side (or a bounded buffer with drop) prevents memory growth, mirroring asyncBridge's bounded buffer. |
