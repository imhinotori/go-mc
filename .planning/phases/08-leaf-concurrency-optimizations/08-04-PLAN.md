<objective>
OPT-02: swap the tracker EXECUTOR for an off-tick diff behind the UNCHANGED `tracker interface{ Tick() }` seam. Today `entityTracker.Tick()` (tracker.go) computes the per-player visibility diff AND sends the packets synchronously on the tick. This plan introduces `asyncTracker` — assigned at the SINGLE swap-point line in `NewTickLoop` (`t.tracker = &entityTracker{loop: t}` → `&asyncTracker{loop: t}`) — whose `Tick()` builds an immutable per-player snapshot ON the owner (positions + a copy of `p.tracked`), SUBMITS the diff MATH to the Wave-0 `trackerPool`, and lets the result rejoin as `trackerDiffReady{playerID, packets}` via the UNCHANGED `applyAsyncResults` seam. `trackerDiffReady.applyTo` then calls `p.client.Send` for each packet and updates `p.tracked` ON THE OWNER.

The load-bearing discipline (08-RESEARCH Pitfall 5): packet EMISSION must stay owner-side because `p.client.Send` enqueues onto the bounded per-player outbound queue that the writeLoop solely owns — the Phase-5 `ChannelQueue` close-vs-send race fix is the precedent. ONLY the diff math (the pure spawn/teleport/remove decision over a position snapshot) goes off-tick. The synchronous `entityTracker` stays in the file as the golden reference, and a test asserts the async tracker emits the SAME packets — proving this is an executor swap, not a behavior change.

This plan touches `tick.go` (the swap-point) and `async.go` (the trackerDiffReady contract), which overlap with the OPT-01 plan's files, so it runs in Wave 2 (after OPT-01 lands). It depends on the 08-01 substrate (trackerPool, asyncIn2, the trackerDiffReady contract).

Purpose: OPT-02 ("async entity tracker runs visibility updates off the main tick and rejoins via the apply-async seam") + its slice of OPT-06 (this subsystem -race clean). The per-player diff scales with entity×player count; moving the math off-tick is the Leaf tracker optimization.
Output: tracker.go (asyncTracker + snapshot builder; entityTracker kept), async.go (trackerDiffReady.applyTo filled), the tests + the swap-point line. New external deps: none (ants landed in 08-01).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Off-tick tracker-diff pool worker → tick goroutine (diff rejoin) | The worker computes the visibility diff over an immutable per-player snapshot and hands an immutable trackerDiffReady (a packet list) to the owner. The worker never touches the live store/player/outbound-queue; the owner emits the packets + updates p.tracked. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-8-12 | Tampering/race | the diff worker calling p.client.Send off-tick, racing the bounded outbound queue / writeLoop | mitigate | The worker ONLY produces a []pk.Packet; trackerDiffReady.applyTo calls p.client.Send on the owner (Pitfall 5 / the Phase-5 ChannelQueue fix). Proven by the Docker -race gate + TestAsyncTrackerSendsOnOwner. |
| T-8-13 | Tampering/race | a diff worker reading the live entityStore/p.tracked while the tick mutates them | mitigate | The snapshot copies positions + p.tracked ON the owner; the closure captures value copies, not pointers (Pitfall 3). Proven by the -race gate. |
| T-8-14 | Tampering | a diff applied to a player who left between submit and apply (nil-deref / send on a closed client) | mitigate | trackerDiffReady.applyTo re-resolves the player by id; absent → DROP (Pitfall 2). Asserted by TestAsyncTrackerLeftPlayerDropped. |
| T-8-15 | Denial of Service | tracker-pool saturation under many players/entities | mitigate | trackerPool is non-blocking bounded (08-01); an overloaded Submit skips the player this tick (recomputes next tick) — never blocks (Pitfall 4). |
