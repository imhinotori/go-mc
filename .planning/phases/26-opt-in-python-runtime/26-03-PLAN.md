<objective>
Build the world-bridge: a Python hook running off-tick may REQUEST a small, capability-gated set of world/entity mutations (set_block + a simple spawn/log). The request is queued to the owner and APPLIED on the tick goroutine through the SAME Phase-23 tick-owned seams (ChunkManager.SetBlock + broadcastBlockUpdate, the spawn path) — never directly off-tick. A READ goes request → tick-snapshot → return-a-copy. The request/apply indirection IS the safety boundary: no live tick-owned handle ever escapes to the off-tick goroutine. Prove the round-trip -race clean, then close THE PHASE GATE.

Purpose: CONTEXT decision 4 (operator-directed, RISK-FLAGGED) — Python CAN touch the world, but ONLY via a bridge back to the tick. The planner scopes the vocabulary MINIMAL (set_block + a simple spawn/log) and leaves the rest incremental. This is the highest-risk surface in the phase, so it is the last plan and carries the full -race + default-static gate.
Output: `server/python_bridge.go` (the request types + owner apply, both builds) + `server/python_bridge_python.go` (the tagged off-tick request producers) + `plugin/python/bridge_python.go` (the python-facing world API) + the worldmutate testdata plugin + the world-bridge -race test + THE GATE.
</objective>
