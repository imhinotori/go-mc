<objective>
Port the bounded-BFS `JigsawPlacement.Placer` (the hard logic of STRUCT-05) + the template_pool/pool-element types + the village `StartGenerator`. This is the data-driven assembly engine: it reads a piece's jigsaw blocks, resolves target pools, finds aligning templates, collision-checks against the placed-piece VoxelShape, and grows the village breadth-first — then hangs the whole thing on a `random_spread` village placement gated on the 5 biome variants.

Purpose: 16-01 delivered "place THIS template here." This plan delivers "decide which templates go where, bounded so the village terminates." Per Pitfall #6, the Placer is bounded by THREE constraints simultaneously (maxDepth + max_distance_from_center + VoxelShape collision) — drop any one and a village grows forever or overlaps itself. It is BFS via a priority-queue work iterator, NOT stack recursion, so the piece-selection RNG draws stay in lockstep with vanilla.

Output: the pool-element model + the Placer + the village StartGenerator wired into the CompositeStartGenerator. Villages place in vanilla positions per biome variant, deterministic per seed. NO visual gate yet (16-03).
</objective>
