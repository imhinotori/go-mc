<objective>
Run the retargeted codegen pipeline against the official Minecraft 26.2 server jar to produce the authoritative proto-776 data as committed Go source. This is the core of the phase: `cd tools && go run . --version 26.2 --extract` downloads the jar (sha1-verified), runs the JDK-25 container extractors + the `net.minecraft.data.Main --all` generator, and emits Go into the runtime module's standard paths. The one genuine residual risk — an extractor importing a `net.minecraft.*` class that 26.2 renamed — surfaces as a LOUD javac compile error, never silent corruption; this plan includes a fix-and-rerun loop for exactly that.

Purpose: GEN-02 (pipeline produces 26.2 data) and GEN-03 (generated 776 data committed as Go source). Hand-transcription of 264+ packets / 29k+ block states / 95 registries / 104 components is a non-starter (Pitfall 2); the jar is ground truth and the generator is the only sanctioned path.
Output: Committed, compiling generated 776 Go source across packets, registries, blocks/states, items, entities, components, and sounds.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mojang CDN → codegen host | The 26.2 server jar + ~147 lang files are downloaded and then executed inside the extractor container (untrusted-origin binary) |
| 26.2 jar bytecode → JDK-25 container | Mojang code runs `--all` to emit reports; isolated in the container, never in runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Tampering | 26.2 server jar integrity | mitigate | Resolve the jar URL from the official `version_manifest_v2.json` → `26.2.json`; verify the downloaded jar's sha1 equals `823e2250d24b3ddac457a60c92a6a941943fcd6a` BEFORE running any extractor over it. download.go already resolves by manifest; add/confirm the checksum gate and abort on mismatch. |
| T-1-04 | Elevation of Privilege | Executing Mojang jar + draft Java extractors | mitigate | Run extraction only inside the hermetic JDK-25 container (or an isolated host JDK), never as part of the runtime. Container output is JSON consumed by the Go host; Java never crosses into the runtime module. |
| T-1-05 | Tampering | Lang/asset download (assetIndex id 32) | accept | Lang files feed only the generated data/lang table; low-value, non-executable text. Manifest-sourced; no separate checksum gate required for v1. |
</threat_model>
